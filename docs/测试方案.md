# Mizan 数据管理系统 — 测试方案

## 背景

当前项目 **完全没有测试基础设施** — 无测试框架、无测试文件、无 CI 流水线。`.gitignore` 中的 `/coverage` 条目表明曾考虑过但从未实施。为了保障代码质量和可维护性，需要从零搭建完整的测试体系。

项目概况：pnpm monorepo（4 apps + 3 packages），Next.js 15 App Router，Prisma 6 + SQLite，NextAuth v4 JWT，Zustand 5，TanStack React Query 5。

---

## 技术选型

| 类型 | 工具 | 选型理由 |
|------|------|----------|
| 单元/集成测试 | **Vitest** | 原生 ESM 支持，与 Next.js 15 模块解析兼容，比 Jest 快，支持 workspace |
| 组件测试 | **@testing-library/react** + jsdom | 业界标准，测试用户行为而非实现细节 |
| E2E 测试 | **Playwright** | 跨浏览器，强大的调试工具，自动等待 |
| Mock HTTP | **MSW** (Mock Service Worker) | 用于 PipelineEngine 集成测试中 mock fetch 调用 |
| 覆盖率 | **@vitest/coverage-v8** | Vitest 原生集成 |
| 测试 DB | **SQLite 临时文件** | Prisma 原生支持，每次测试独立文件，无需 Docker |

## 实施路线图

### 阶段 0：基础设施搭建（2-3 天）

**目标**：安装依赖、创建配置、提供测试工具函数。

**依赖安装**（root devDependencies）：
- `vitest`、`@vitest/coverage-v8`、`@vitejs/plugin-react`
- `@testing-library/react`、`@testing-library/jest-dom`、`@testing-library/user-event`
- `jsdom`、`msw`

**新增包**：`packages/test-config/` — 共享测试配置和工具函数
- `vitest.base.ts` — 基础 Vitest 配置
- `vitest.dom.ts` — jsdom 环境配置（引用 base 并覆盖 environment）
- `src/prisma-test-client.ts` — 创建隔离的测试 SQLite 数据库

```typescript
// 核心函数：每次调用创建独立的 SQLite 临时文件数据库
export async function createTestPrismaClient(): Promise<{
  prisma: PrismaClient;
  dbPath: string;
  cleanup: () => Promise<void>;
}>;
```

- `src/session-mock.ts` — Auth session mock 工厂

```typescript
export function createMockSession(overrides?): MockSession;
export function mockGetServerSession(session?);  // vi.mock("next-auth")
export function mockUnauthenticated();
```

- `src/test-factory.ts` — 测试数据工厂

```typescript
// 生成 Prisma.create 兼容的数据对象
TestFactory.user(overrides?)
TestFactory.schema(overrides?)
TestFactory.tableDefinition(overrides?)
TestFactory.column(overrides?)
// 可按需扩展 PipelineStep, Dashboard 等
```

- `package.json` — 导出 `./base`、`./dom`、`./test-factory`、`./session-mock`、`./prisma-test`

**每个 app 新增 vitest.config.ts**（核心变更文件）：
- `apps/core/vitest.config.ts` — 配置 `@` alias 映射到 `./src`，指向 test/setup.ts
- `apps/data/vitest.config.ts`
- `apps/admin/vitest.config.ts`
- `packages/shared-ui/vitest.config.ts`（使用 jsdom 环境）
- `packages/shared-lib/vitest.config.ts`

**turbo.json 新增 test 任务**：
```json
"test": { "dependsOn": ["^build"], "outputs": ["coverage/**"] },
"test:e2e": { "dependsOn": ["build"] }
```

**每个 package.json 新增 scripts**：
```json
"scripts": {
  "test": "vitest run",
  "test:watch": "vitest",
  "test:coverage": "vitest run --coverage"
}
```

**root package.json 新增脚本**：
```json
"test": "turbo run test",
"test:core": "pnpm --filter @mizan/app-core test",
"test:shared-ui": "pnpm --filter @mizan/shared-ui test"
```

**`apps/core/test/setup.ts`** — 全局 setup 文件：
- 在 `beforeAll` 中创建测试数据库，mock `@mizan/database` 和 `@/lib/db/prisma` 指向测试实例
- 解决两个 PrismaClient 实例（package vs app）的 mock 问题

**.gitignore 添加** `.test-db/`

### 阶段 1：纯函数单元测试（3-4 天，~120 个测试用例）

### 阶段 2：API 集成测试（5-7 天，~60 个测试用例）

**测试文件位置**：`apps/core/test/api/<route-path>.test.ts`

**关键模式**：使用 `@mizan/test-config` 的工具函数，直接 import route handler 并调用。

**完整测试流程示例**：
```typescript
// apps/core/test/api/schemas.test.ts
import { GET, POST } from "@/app/api/schemas/route";
import { NextRequest } from "next/server";

describe("POST /api/schemas", () => {
  it("创建 schema（有效输入）", async () => {
    const req = new NextRequest("http://localhost/api/schemas", {
      method: "POST",
      body: JSON.stringify({ name: "测试 Schema", description: "描述" }),
    });
    const response = await POST(req);
    expect(response.status).toBe(201);
    const data = await response.json();
    expect(data.name).toBe("测试 Schema");
  });

  it("空名称返回 400", async () => {
    // ...
  });

  it("未登录返回 401", async () => {
    mockUnauthenticated();
    // ...
    expect(response.status).toBe(401);
  });
});
```

**优先测试的 API 路由**：

| 路由 | 测试场景 |
|------|---------|
| `POST /api/schemas` | 成功创建、空名称、重复名称、未登录 |
| `GET /api/schemas` | 列表返回、按用户过滤 |
| `GET/PUT/DELETE /api/schemas/[schemaId]` | 获取、更新、删除、404 不存在、跨用户隔离 |
| `POST /api/schemas/[schemaId]/tables` | 含列定义创建、重复表名、schema 不存在 |
| `GET/PUT/DELETE /api/tables/[tableId]` | CRUD + 权限验证 |
| `GET /api/tables/[tableId]/data` | 分页、排序、过滤、SQL 注入防护 |
| `POST /api/tables/[tableId]/batch-import` | 批量 upsert、列映射、类型转换 |
| `POST /api/query` | 动态查询执行、安全过滤 |
| `POST /api/auth/register` | 注册成功、重复邮箱 |
| `POST /api/upload` | 文件上传（测试 mock 文件） |

**数据隔离策略**：
- `apps/core/test/setup.ts` 中全局创建一次测试 DB
- 每个 `describe` 的 `beforeEach` 中清理数据并重新 seed
- 使用 `TestFactory` 生成测试数据，包含测试用户（与 mock session 的 ID 匹配）

### 阶段 3：组件测试（5-8 天，~100 个测试用例）

**技术栈**：Vitest + jsdom + @testing-library/react + @testing-library/user-event

**测试文件位置**：与组件文件放在同一目录（`component-name.test.tsx`）

**Provider 封装**（`apps/core/test/test-utils.tsx`）：
```typescript
// 提供 SessionProvider + QueryClientProvider 包装
export function createWrapper() { /* ... */ }
```

**测试重点**：

**shared-ui 基础组件**（25 个组件，每个 3-4 个测试）：
- button：渲染子元素、variant/disabled/size class、点击事件
- dialog：打开/关闭、内容渲染、aria 属性
- select/combobox：选项渲染、选择行为、搜索过滤
- input/badge/card/tabs/checkbox/switch 等基础组件

**DDL Designer 组件集**（`apps/core/src/components/ddl-designer/`）：
- column-editor：渲染列、添加/删除/重新排序列、空列名验证
- ddl-preview：展示生成的 SQL、随状态更新
- foreign-key-editor：添加 FK、选择源列/目标表
- index-editor：添加索引、切换 unique
- trigger-editor：timing/event/logic 编辑

**Pipeline 组件集**（`apps/core/src/components/pipeline/`）：
- workflow-pipeline-builder：渲染 canvas、节点、边
- step-config-dialog：各 stepType 的动态表单渲染
- add-step-dialog：步骤类型选择、分组过滤
- pipeline-step-card：状态指示器、标签渲染

**Data 组件集**：
- dynamic-data-table：大数据渲染、分页控制、排序
- filter-dialog：添加/删除过滤条件
- batch-import-dialog：上传 UX、进度显示、错误显示

**Mock 策略**：
- Zustand store：使用 store 真实实例（`useXxxStore.getState()`），或 vi.mock
- next-auth：mock `useSession` hook
- @tanstack/react-query：wrap 在 QueryClientProvider（retry:false）
- @xyflow/react：mock 库渲染
- next/navigation：mock useRouter/useParams

### 阶段 4：E2E 测试（3-5 天，~25 个测试用例）

**配置**：`apps/core/e2e/playwright.config.ts`

- 浏览器：chromium（CI 中可并行）
- 基础 URL：`http://localhost:3000`
- retries：CI 中 2 次
- 自动截图：仅失败时

**5 个关键用户旅程**：

```
1. 认证流程：注册 → 登录 → 跳转首页（测试登录保护和 session)
2. Schema + Table CRUD：创建 schema → 创建表 → DDL Designer 设计列 → 执行 DDL → 验证 CREATED 状态
3. 数据操作：导航到数据视图 → 添加行 → 编辑 → 保存 → 验证数据显示
4. Pipeline 创建执行：添加 source → transform → output 步骤 → 连接 → 执行 → 验证 COMPLETED
5. Dashboard + 图表：创建看板 → 添加图表 widget → 配置数据源 → 验证渲染
```

## 跨领域问题处理

### 两个 PrismaClient 实例
项目存在两处 Prisma 单例：`@mizan/database` 和 `apps/core/src/lib/db/prisma.ts`。在 `test/setup.ts` 中 `vi.mock` 两个 import path 指向同一个测试 PrismaClient。

### Auth 模块 mock
所有 ~70 个 route handler 都使用 `getServerSession(authOptions)`。提供集中的 `mockGetServerSession()` / `mockUnauthenticated()` 工具函数。

### Turborepo 缓存配置
`turbo.json` 中 `test` 任务的 `inputs` 包含 `src/**/*.ts`、`test/**/*`、`vitest.config.ts`，仅当这些文件变化时重新运行测试。

### CI 流水线
推荐 GitHub Actions，3 个独立 job（lint/unit+integration/e2e）并行：
- unit+integration job：`pnpm install` → `pnpm db:generate` → `turbo run test`
- e2e job：安装 Playwright 浏览器 → `pnpm build` → `playwright test`
- 产物上传：lcov 覆盖率报告、Playwright HTML 报告

## 验证方式

1. **阶段 0 验证**：`pnpm test` 运行后显示 "No tests found" 但正常退出（`passWithNoTests: true`）
2. **阶段 1 验证**：`pnpm test:core -- --testPathPattern=dynamic-query-builder` 运行指定测试文件，全部通过
3. **阶段 2 验证**：`pnpm test:core -- --testPathPattern=test/api` 运行所有集成测试，验证测试数据库文件存在且测试后自动清理
4. **阶段 3 验证**：`pnpm --filter @mizan/shared-ui test` 运行 UI 组件测试
5. **阶段 4 验证**：`pnpm exec turbo run test:e2e` 启动 dev server 并运行 Playwright 测试
