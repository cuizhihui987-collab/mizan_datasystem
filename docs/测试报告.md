## 已发现并修复的问题

在测试过程中发现了以下代码问题并已修复：

### 1. 丢失的 `stepTypeMeta` 条目
- **问题**：`step-config-registry.ts` 中 `stepTypeMeta` 缺少 `transform_filter`、`transform_sort`、`transform_custom_script`、`transform_union` 条目，而 `stepConfigFields` 已定义这些类型的配置字段
- **影响**：运行时 `stepTypeMeta[stepType]` 可能返回 `undefined`，导致 UI 显示异常
- **修复**：在 `stepTypeMeta` 中补充了缺失的条目

### 2. `PipelineEngine` 辅助函数未导出
- **问题**：`pipeline-engine.ts` 中的 `generatePhysicalName()`、`safeIdentifier()`、`isSQLSafe()` 是纯函数且可复用，但未添加 `export` 关键字
- **影响**：无法在外部单元测试或其它模块中直接使用
- **修复**：添加了 `export` 关键字

## 代码质量优化建议

### 1. SQL 生成中的多余空格（低优先级）
`dynamic-query-builder.ts` 在 `buildSelectQuery` 方法中，当 `whereSQL` 为空时，生成的 SQL 包含多余空格（`SELECT * FROM "table"  ORDER BY ...`）。建议将 SQL 模板改为使用数组 join：
```
const parts = [`SELECT ${selectCols} FROM ${tableRef}`];
if (whereSQL) parts.push(whereSQL);
parts.push(orderSQL, `LIMIT ${pageSize} OFFSET ${offset}`);
return parts.join(" ");
```

### 2. 统一的 Auth 守卫（中等优先级）
所有 ~70 个 route handler 重复同样的 auth 检查模式：
```typescript
const session = await getServerSession(authOptions);
if (!session?.user?.id) {
  return NextResponse.json({ error: "未登录" }, { status: 401 });
}
```
建议提取为可复用的 `requireAuth()` 辅助函数，减少重复代码并降低遗漏风险。

### 3. 两个 PrismaClient 实例（中等优先级）
项目存在两个 Prisma 单例：`@mizan/database` 和 `apps/core/src/lib/db/prisma.ts`。在测试中需要同时 mock 两者。建议统一为一个实例。

### 4. JSON 字符串字段（低优先级）
Prisma schema 中多个字段使用 `String` 类型存储 JSON 数据（如 `edges String @default("[]")`、`config String @default("{}")`），需要在代码中手动 `JSON.parse/stringify`。建议考虑类型安全方案。

### 5. 业务逻辑内联在路由处理器中（高优先级）
`batch-import/route.ts`（223 行）、`upload/route.ts`（163 行）、`pipeline-engine.ts`（860 行）等包含大量内联业务逻辑，混合了 DB 操作和 SQL 生成。建议逐步将业务逻辑提取到独立的 service 层，以提高可测试性和可维护性。

### 6. 测试覆盖率缺口（待改进）

| 模块 | 优先级 | 建议 |
|------|-------|------|
| `pipeline-engine.ts` 核心执行逻辑 | **高** | 需要集成测试（mock Prisma），覆盖 executeDAG 的完整流程 |
| `data-importer.ts` | **高** | 批量导入逻辑的核心模块，需要 mock 文件系统和 Prisma 的集成测试 |
| `spreadsheet-parser.ts` | **中** | 使用测试 fixture 文件进行解析测试 |
| `dynamic-data-table.tsx` | **中** | 大数据渲染和分页交互的组件测试 |
| `ddl-designer` 组件 | **中** | 列编辑器、FK 编辑器、SQL 预览的业务组件测试 |
| E2E 测试 | **中** | Playwright 覆盖 5 个关键用户旅程 |
| `storage/index.ts` | **低** | 本地/S3 存储服务测试 |

### 7. CI/CD 集成
建议配置 GitHub Actions 自动运行测试流水线：
- 分支推送时自动运行 `lint` + `test`
- PR 合并前要求测试通过
- 生成覆盖率报告并上传

## 结论

本次测试实施从零搭建了完整的测试基础设施（Vitest + @testing-library/react + jsdom），完成了 **214 个测试用例** 的编写和执行，全部通过。覆盖了核心纯函数模块、Zustand 状态管理、API 路由和 UI 基础组件。在测试过程中发现并修复了 2 个代码缺陷，并提出了 7 项优化建议。后续建议优先补充 `pipeline-engine` 和 `data-importer` 等复杂模块的测试覆盖。
